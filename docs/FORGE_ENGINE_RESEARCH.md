# GPUI Shell engine and Forge

Reviewed 2026-09-08. Scope: whether the supplied [engine documentation](https://gpui-kit.com/shell/engine/) helps improve Forge's native editor experience without changing Forge functionality.

**Recommendation: keep Forge's native editor integration; do not adopt GPUI Shell for this work.** Shell supplies JavaScript extension points for building application views. Its own architecture leaves text editing with the Rust host. It does not supply MongoDB completion semantics or make an existing editor more responsive merely by being embedded. That conclusion follows from its documented responsibility split, not an editor benchmark. [Shell introduction](https://gpui-kit.com/shell/), [shell public API](https://github.com/longbridge/gpui-kit/blob/3a25a738d8b85c208435b4ce76286747e331af5b/crates/shell/src/lib.rs)

## What the engine actually does

Shell evaluates JavaScript with QuickJS through `rquickjs`. Script code describes GPUI views; Rust retains a snapshot and materializes native elements during repaint. It uses no WebView, DOM, or Node.js runtime. Its intended use is application extension and scripted UI composition. [Shell introduction](https://gpui-kit.com/shell/)

The VM shares GPUI's main thread and is neither `Send` nor `Sync`. Background I/O may run elsewhere, but JavaScript computation still competes with UI work. QuickJS has no JIT. The documented time limits are 50 ms for rendering and 500 ms for event handlers; these are interruption ceilings, not interaction-latency guarantees. Cached repaints avoid JavaScript, while dirty views rebuild their descriptions. The supplied page reports both favorable synthetic measurements and a live workload missing its 120 FPS target. Neither establishes how Forge typing or completion would behave. [Engine model and measurements](https://gpui-kit.com/shell/engine/)

## Embedding means adding a runtime and bridge

A host initializes Shell, creates `ShellRuntime`, loads a view type, instantiates it, and mounts `ScriptView` under `ShellRoot`. That root owns overlay and focus behavior. Shell also enables `gpui-base/inspector` across Cargo's unified feature graph, including release builds. This is a meaningful integration change, not an editor option. [Hosting](https://gpui-kit.com/shell/hosting/)

Rust services can be registered as `HostModule` ES-module exports. Synchronous functions hold the UI thread; `async_function` moves its future onto GPUI's background executor. The boundary carries JSON-like `HostValue` cases, with numbers represented as `f64`, rather than native BSON or an existing MongoDB shell API. Exposing database operations would require application-owned APIs and faithful BSON conversion. Type declarations describe those exports; they are not a MongoDB language service. [HostModule](https://gpui-kit.com/shell/host-module/)

Shell dependencies are Git-sourced ES modules; its package model does not provide Node compatibility or `require`. This offers no direct replacement for OpenMango's existing `@mongosh` sidecar packages, and replacing execution is outside the requested editor work. [Dependencies](https://gpui-kit.com/shell/dependencies/), [local sidecar manifest](../tools/forge-sidecar/package.json)

## Compatibility with this checkout

- [Cargo.toml](../Cargo.toml) requests `gpui-kit` 0.6.0 with `tree-sitter-languages`; [Cargo.lock](../Cargo.lock) resolves registry versions 0.6.0 for Kit, Base, and Component, with `gpui-pre` 0.3.4.
- Both the installed 0.6.0 facade and current upstream facade have no `shell` export, dependency, or feature. Consequently, the website's `gpui_kit::shell` examples cannot be copied into this checkout as documented. [Upstream facade source](https://github.com/longbridge/gpui-kit/blob/3a25a738d8b85c208435b4ce76286747e331af5b/crates/kit/src/lib.rs), [facade manifest](https://github.com/longbridge/gpui-kit/blob/3a25a738d8b85c208435b4ce76286747e331af5b/crates/kit/Cargo.toml)
- Upstream's separate `gpui-shell` crate declares version 0.6.0 but `publish = false`. Its source explicitly marks the scripting/runtime interfaces experimental. A matching version label does not establish compatibility with this checkout. [Shell manifest](https://github.com/longbridge/gpui-kit/blob/3a25a738d8b85c208435b4ce76286747e331af5b/crates/shell/Cargo.toml), [experimental API notice](https://github.com/longbridge/gpui-kit/blob/3a25a738d8b85c208435b4ce76286747e331af5b/crates/shell/src/lib.rs)

Verification covered the complete engine page, related primary documentation, upstream source, and installed dependency manifests/exports. No application was launched, dependencies changed, or runtime benchmark performed. Git-based embedding compatibility and the incremental binary/memory cost in OpenMango remain unverified; neither needs resolving for the requested editor improvement.
